# ADR 0004 — AGENTS.md canonical, tools via thin adapters

- **Status:** Accepted
- **Date:** 2026-09-10
- **Wave:** 004
- **Related:** [0001](0001-name-scope.md), `docs/what/adapters.md`

## Context

Every agent reads a different instruction file (`CLAUDE.md`, `GEMINI.md`,
Copilot instructions, Cursor rules, …). Duplicating process docs per tool
guarantees drift; picking one tool betrays agnosticism.

## Decision

| Rule | Detail |
| ---- | ------ |
| Canonical file | **`AGENTS.md`** at repo root (open, Linux Foundation–stewarded convention) |
| Adapters | Thin WHW-managed pointers generated by `whw adapters sync`; unique content lives only in `AGENTS.md` |
| Manifest | `.whw/adapters.json` records `{tools, files}`; the `agents-parity` gate verifies it |
| Native tools | Codex/OpenCode/Aider need no pointer (documented, recorded as native) |
| Overrides | Project `templates/adapters/*.md` may restyle pointers, never fork content |

### Options considered

| Option | Upside | Downside |
| ------ | ------ | -------- |
| Full doc per tool | Native feel each | N copies drift immediately |
| One tool only | Simple | Vendor lock; excludes everyone else |
| Canonical + pointers (chosen) | Single truth, broad reach | Pointer files need regen on tool changes (cheap, scripted) |

## Consequences

### Positive

- Process edits happen once, in `AGENTS.md`, verified by a gate.
- New tools onboard by adding one pointer template.

### Negative / trade-offs

- Tool-specific expressiveness (glob-scoped rules) stays second-class by
  design — escape hatch documented, not encouraged.
