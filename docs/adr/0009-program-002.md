## Context

Program 001 shipped WHW v0.1.0 (CLI, SQL planning, gates, roles, skills, docs)
and closed on 2026-09-10. A prompt × plan × implementation review found the
surface complete but the *self-application* incomplete: `npx @fabioeloi/whw`
404s, derived checkpoints pollute git, evidence strings are not re-runnable,
three commits landed after close with no wave, and `whw run` / `whw handoff`
were never exercised. CI is green as of `c36e1d9`.

This program hardens how WHW treats itself and makes the public quick start
true. Work lands on real branches/PRs against `origin` so history *is* the
A–E demonstration Program 001 lacked. Outcome: a published, evidence-gated
v0.1.1 (or later patch) plus a maintenance policy so post-close drift cannot
recur.

## Execution

- One wave = PRs A–E (plan → build → verify → decide → close); a wave is done
  only when **E** merges. **Real PRs against `origin`**, not solo squash-to-main.
- First wave (007 A) is documentation-first: this charter + planning seeds +
  `docs/plan.md`. Implementation (007 B) waits on an explicit operator go.
- Final wave is the program close: inventory gate + retrospective addendum.
- Do not start the next wave until `main` is green.
- Branch/commit conventions: `docs/how/conventions.md`.
- Historic Program 001 evidence strings are **not rewritten** (`done` is
  terminal). Retro findings land as `whw note` on `wave006-E`.
- npm publish is external and irreversible — confirm at wave 007 B.
